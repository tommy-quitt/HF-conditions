# Agent rules for this repository

`SPEC.md` is authoritative. `DEVIATIONS.md` records the specific, deliberate places
where this implementation departs from it (all due to the GitHub-only hosting
constraint) and why. Do not silently change product requirements or scoring formulas
beyond what `DEVIATIONS.md` already documents.

- Scoring logic belongs in `packages/core`. It must remain deterministic and must never
  make a network or filesystem call — this is what lets it run unchanged in both the
  Node collector script and the browser bundle.
- External systems (NOAA, PSKReporter, RBN, HolyCluster) are accessed only through
  adapters in the collector, never inlined into scoring or UI code.
- Every external adapter must isolate its own failure: one source failing must never
  take down the others, and must never be silently treated as a zero score. Follow
  spec §15/§19/§26 — renormalize remaining source weights and lower confidence instead.
- TypeScript strict mode stays enabled everywhere. Avoid `any` except at untrusted
  external boundaries (raw API/Telnet responses), and validate that data with the Zod
  schemas in `packages/shared` before it crosses into `packages/core`.
- Never fabricate a value for an unavailable data source. Missing data is represented
  as missing, with confidence and UI reacting accordingly — not defaulted to 0 or to a
  plausible-looking placeholder.
- Business logic changes require tests. Run `npm run typecheck`, `npm run lint`, and
  `npm test` before considering a task finished; fix failures before moving on.
- Never commit secrets. Data-source hostnames/ports are configuration
  (`DX_CLUSTER_HOST` etc. per spec §7.4), not hardcoded.
- No score or explanation is ever generated by an LLM (spec §6, §36). Explanations are
  rule/template-generated from the stored component scores.
- If a real external source behaves differently than this spec assumed, do not work
  around it ad hoc: isolate the discrepancy behind its adapter, document it in
  `DEVIATIONS.md`, and implement the safest practical fallback (spec §37).
